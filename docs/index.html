Scope / Discovery / Scale

Reusable execution is not
automatic model understanding.

Capability and limits guide

The current agent supports many questions inside one configured schema subset. It does not automatically search every model, discover all fields, or fetch model-authored instructions at runtime.

IMPLEMENTED

Bounded single-model analytics

Approved metrics, dimensions, exact filters, date ranges, ranked results, and compiler-backed DAX advice. These are reusable combinations, not unrestricted query generation.

REQUIRES ONBOARDING

Another model's meaning

Schema, measures, relationships, definitions, permissions, and mappings must be obtained and validated. Changing only a dataset ID is not enough.

NOT YET DEMONSTRATED

Automatic multi-model discovery

A model catalog, focused metadata retrieval, routing, schema refresh, and cross-model interpretation remain separate work. No model-count or concurrency ceiling has been measured.

Not exposed does not mean nonexistent. Owner/creator details are excluded from this PoC's tools. That does not prove whether they exist in the underlying semantic model. The agent must distinguish restricted scope, unknown metadata, verified absence, and denied access.

Second-model probe: structure discovery succeeded

A genuinely different model accepted three constant DAX queries. Its definition was retrieved automatically using the documented Fabric API: 78 tables, 694 columns, 17 measures, and 79 relationships, including hidden/generated objects.

This used existing read/write model permissions. No nonempty object descriptions were found; authored-instruction discovery remains unproven. The schema has not been wired into the agent, and this is not evidence of automatic business understanding or read-only-user metadata access.

Observed constant-query request times: 823 / 461 / 538 ms. Three sequential samples, not a benchmark, concurrency test, or complete-chat latency.

What a useful scalability test measures

Metadata coverage and onboarding effort; correct model routing; measure/answer accuracy; schema-drift behavior; permission boundaries; and metadata, query, and complete-chat latency separately.

The API documents 120 requests/minute/user and result-size limits. Those are service constraints, not proof of agent throughput. A second report is only another model if its dataset identity differs.

Production questions still matter

Does RLS automatically make this safe?

RLS follows the actual execution identity and workspace role. Verify restricted users, Build permission, and the model's sensitive fields. Agent instructions do not enforce authorization.

Can it answer any question?

No. The current model contract and query compiler expose a finite approved subset. An unsupported field may still exist in the full model. Automatic whole-model discovery and multi-model routing are not implemented.

Is Fabric capacity or MCP required?

A Fabric data agent is not required for the connector/REST route. Power BI licensing still applies. Hosted Power BI MCP is a separate optional integration; its query-generation tool has Copilot entitlement requirements.

Are these real business results?

The UI screenshots are real. Public example names and numbers are synthetic. No customer result rows or private conversation transcripts are published here.
